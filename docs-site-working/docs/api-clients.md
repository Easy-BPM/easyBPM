# EasyBPM API clients

API clients are non-human service identities for integrations that call EasyBPM REST APIs. They use revocable credentials managed by EasyBPM and work with either local-login or OIDC/Keycloak deployments.

## Create and store a credential

An administrator with `MANAGE_API_CLIENTS` opens **API Clients** in the Admin console, chooses a name, expiry, and least-privilege permissions, then creates the client. The credential is displayed once in this form:

```text
ebpm_<selector>.<secret>
```

Copy it directly into a secret manager. EasyBPM stores only the selector and a BCrypt cost-12 hash of the secret; the plaintext cannot be recovered later. Do not place credentials in source control, URLs, query parameters, screenshots, support tickets, or logs.

## Call the API

Send the credential as a bearer token:

```bash
curl https://easybpm.example.com/processes \
  -H "Authorization: Bearer $EASYBPM_API_CREDENTIAL"
```

The API client receives only its explicitly assigned EasyBPM permissions. Existing endpoint authorization remains authoritative, so an insufficiently scoped client receives HTTP 403. API clients can never manage API clients.

Malformed, unknown, expired, rotated, and revoked credentials all receive the same generic HTTP 401 response. Expiry is mandatory; the default is 90 days and the supported lifetime is one hour through 365 days.

## Rotate and revoke

Rotation creates a new one-time credential and invalidates the previous credential immediately while preserving the service identity and assigned permissions. Expired clients may be rotated with a new future expiry. Revocation is immediate and permanent; a revoked client cannot be edited, rotated, or restored.

Lifecycle changes require the latest version and the Admin console supplies it through `If-Match`. API integrations do not need this header for ordinary runtime API calls.

## Audit and retention

The Admin console records lifecycle changes and authenticated use, including time, client, credential generation, servlet-resolved remote address, HTTP method, sanitized path, status, request ID, and duration. Authorization headers, credentials, secret hashes, bodies, and query values are never recorded.
Audit request IDs are generated by EasyBPM; caller-supplied correlation headers are not trusted or persisted.

Audit retention defaults to 90 days and can be configured from 30 through 3650 days:

```text
EASYBPM_API_CLIENT_AUDIT_RETENTION_DAYS=180
EASYBPM_API_CLIENT_AUDIT_RETENTION_CRON="0 15 2 * * *"
EASYBPM_API_CLIENT_AUDIT_FINALIZATION_RECOVERY_MS=60000
EASYBPM_API_CLIENT_FINALIZATION_STALE_MINUTES=60
```

Cleanup runs nightly in batches of at most 5,000 records.
Use-audit rows are created before an authenticated request is dispatched. Completion is retried independently, and a scheduled recovery marks stale incomplete rows explicitly rather than silently losing their audit outcome.

## Administrator permissions

- `VIEW_API_CLIENTS` reads clients and audit history.
- `MANAGE_API_CLIENTS` creates, edits, rotates, and revokes clients and also grants read access.

The configured local bootstrap administrator group is reconciled with these permissions at startup. For Keycloak, assign `easybpm-admin-api-clients-read` or `easybpm-admin-api-clients-manage`; the development realm includes both roles. Managers may delegate only permissions they currently hold, and the two API-client administration permissions are never delegable to service identities.
