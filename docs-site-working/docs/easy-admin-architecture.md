# Easy BPM Admin: Architecture & Components

## Project Structure

```
easy-bpm-admin/
├── index.html              # Entry point (HTML shell)
├── index.tsx               # React root render
├── App.tsx                 # Root component with routing logic
│
├── components/
│   ├── Sidebar.tsx         # Navigation sidebar
│   └── ...                 # Other UI components (generated by views)
│
├── services/
│   └── adminService.ts     # API integration layer (single responsibility)
│
├── types.ts                # TypeScript interfaces for backend contracts
│
├── vite.config.ts          # Build configuration
├── tsconfig.json           # TypeScript compiler options
├── package.json            # Dependencies and scripts
│
└── dist/                   # Production build output (generated by 'npm run build')
```

## Core Components

### App.tsx (Root Component)

**Responsibility**: Orchestrate view routing, authentication state, and user context

**Key Exports**:
- `App` - Main component exported to DOM

**Key Features**:
- Login/logout logic via `handleLogin()` / `handleLogout()`
- View routing based on `currentView` state variable
- User context storage in `currentUser` state
- Sidebar navigation integration
- Initial dashboard render for authenticated users

**Code Structure**:
```typescript
const [currentUser, setCurrentUser] = useState<string | null>(null);
const [currentView, setCurrentView] = useState('dashboard');

const renderView = () => {
  switch (currentView) {
    case 'dashboard': return <DashboardView ... />;
    case 'instances': return <InstanceExplorerView />;
    case 'workflows': return <WorkflowCatalogView />;
    // ...
  }
};
```

**Lifecycle**:
1. Check if user is authenticated (`currentUser !== null`)
2. If not, render `LoginView`
3. If yes, render `MainApp` with navigation sidebar and dynamic view

#### Lifecycle Operations

**Stop Instance**:

**Delete Instance**:
```typescript
const handleDeleteInstance = async (instanceId: number) => {
```

```typescript
const handleSubmit = async (e: React.FormEvent) => {
  e.preventDefault();
  setLoading(true);
  try {
    const response = await fetch(`${API_BASE_URL}/login`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ username, password })

  } finally {
```

## Service Layer: adminService.ts

**Responsibility**: Single integration point for all backend API calls with mock support

**Design Principle**: Single Responsibility - all HTTP logic centralized

### Configuration

```typescript
const API_BASE_URL = (import.meta.env.VITE_API_BASE_URL as string | undefined) ?? 'http://localhost:8085';
const USE_MOCK = false; // Toggle mock/real API
```

### Core Methods

#### Instance Management

```typescript
// Get paginated instances
getProcessInstances(page: number, size: number): Promise<Page<ProcessInstance>>

// Get a single instance by ID
findInstanceById(instanceId: number): Promise<ProcessInstance | null>

// Stop running instance (safe cancellation)
stopInstance(instanceId: number): Promise<void>

// Delete instance (hard delete with cascade)
deleteInstance(instanceId: number): Promise<void>

// Move execution node
moveNode(instanceId: number, payload: MoveNodePayload): Promise<void>
```

#### Variable Management

```typescript
// Get instance variables
getInstanceVariables(instanceId: number): Promise<ProcessVariable[]>

// Assign/update variables
assignVariables(instanceId: number, vars: Record<string, unknown>): Promise<void>
```

#### Definition Management

```typescript
// Get all workflow definitions
getWorkflowDefinitions(page: number, size: number): Promise<Page<ProcessDefinition>>

// Get single definition
getDefinitionById(defId: string): Promise<ProcessDefinition | null>
```

### Mock Mode Implementation

When `USE_MOCK = true`:

1. Service methods return synthetic data immediately
2. Small delay simulated via `delay()` function (250-350ms) for UX
3. State mutations applied locally (no backend sync)
4. Useful for UI development, testing, and demos

Mock data examples:
```typescript
const MOCK_INSTANCES: ProcessInstance[] = [
  {
    id: 1001,
    processDefinitionName: 'Order Fulfillment',
    status: 'ACTIVE',
    currentNode: ['user-review'],
    // ...
  }
];
```

### Error Handling

All methods use try-catch at call sites:

```typescript
try {
  const instances = await adminService.getProcessInstances(0, 20);
  setInstances(instances.content);
} catch (error) {
  setError(`Failed to fetch instances: ${error.message}`);
}
```

HTTP-level errors:

```typescript
const res = await fetch(url);
if (!res.ok) {
  throw new Error(`HTTP ${res.status}: ${res.statusText}`);
}
return res.json();
```

## Type Contracts: types.ts

**Responsibility**: Define TypeScript interfaces matching backend models

### ProcessInstance

```typescript
interface ProcessInstance {
  id: number;                      // Unique instance ID
  processDefinitionId?: number;    // Reference to definition
  processDefinitionName?: string;  // For display
  status: string;                  // ACTIVE, PAUSED, CANCELLED, COMPLETED
  currentNode?: string[];          // Array of current node IDs
  nodeHistory?: string[];          // Execution path taken
  createdAt: string;               // ISO 8601 timestamp
  updatedAt: string;               // ISO 8601 timestamp
}
```

### ProcessDefinition

```typescript
interface ProcessDefinition {
  id: string;              // Unique definition ID
  name: string;            // Display name
  key?: string;            // Stable identifier (NOT human-readable)
  description?: string;    // Optional metadata
  version: number;         // Version number
}
```

### ProcessVariable

```typescript
interface ProcessVariable {
```

## State Management Approach

**Design**: React Hooks (no Redux/Context API)

**Why?**:
- Simpler codebase for small-to-medium applications
- Reduced boilerplate
- Easier to understand data flow
- Sufficient for current feature set

**Pattern**:
```typescript
// Local component state
const [instances, setInstances] = useState<ProcessInstance[]>([]);
const [loading, setLoading] = useState(false);

// Effect for side effects (API calls)
useEffect(() => {
  const fetchData = async () => {
    setLoading(true);
    const data = await adminService.getProcessInstances(0, 20);
    setInstances(data.content);
    setLoading(false);
  };
  fetchData();
}, []); // Run once on mount
```

**If State Grows**:
Consider migration to:
- **Context API** - For theme, authentication, user preferences
- **Zustand** - For shared state across components
- **Redux** - For complex state with time-travel debugging

## Performance Considerations

### Bundle Size

Current: **217 KB** uncompressed, **66 KB** gzipped

Breakdown:
- React/DOM: ~42 KB (gzipped)
- Lucide icons: ~12 KB (gzipped)
- App code: ~12 KB (gzipped)

### Optimization Opportunities

1. **Code Splitting**: Use `React.lazy()` for route-based splits
2. **Image Optimization**: Compress SVGs and icons
3. **Memoization**: Use `React.memo()` for expensive renders
4. **Virtual Lists**: For large instance lists (1000+ items)

### Network

- **API Calls**: Debounce searches, cache responses
- **Pagination**: Load on demand (20 items per page default)
- **Auto-refresh**: Configurable interval (default 30s)

## Security Architecture

### Authentication

1. **Login Flow**: Username/password sent to `/login` endpoint
2. **Token Storage**: Session token stored in memory (lost on page reload)
3. **Backend Validation**: All API calls checked for authorization

### Authorization

Backend enforces role-based access control (RBAC):
- **Admin**: Full access
- **Operator**: Limited to assigned instances
- **Viewer**: Read-only access

### No Direct DOM Access to Secrets

- Credentials not logged to console
- API tokens not exposed in network tab
- Process variables stored server-side only

## Debugging & Development

### Browser DevTools

1. **Console**: React warnings, custom logs
